Executive Overview & Personal ERP Philosophy

Traditional personal finance software operates asynchronously and reactively: users manually log expenses long after transactions occur, with zero awareness of spatial mobility, operational task commitments, or real-time context. This leads to high cognitive load, missed bill deadlines, delayed cash tracking, and incomplete records.

Apex LifeOS resolves this friction by operating as a Personal Enterprise Resource Planning (ERP) platform. It bridges three core domains into a unified, synchronized reactive runtime:

Domain A: Finance
Liquid Ledger & Cash Vault

Multi-currency balance sheets, accounts, monthly budgets, physical cash/ATM wallet, and zero-shot AI transaction parsing.

Domain B: Mobility
Telemetry & Geofencing

Continuous GPS velocity tracking, traffic-jam hysteresis filtering, fuel/fare estimation, and spatial geofence payment reminders.

Domain C: Operations
Daily Task-Ledger Bridge

Payable bills, receivable milestones, recurring subscription burn rates, peer IOUs, and personal asset valuations.

Security Architecture & Threat Defense

Apex LifeOS handles sensitive personal telemetry, location trails, and financial records. The platform implements an end-to-end Zero-Trust posture across AI invocation, administrative governance, hardware sessions, and database access.

DEFENSE-IN-DEPTH 4-Tier AI Prompt Injection Mitigation Matrix

Natural language AI input fields are susceptible to adversarial prompt injection. Apex LifeOS executes a four-phase defensive barrier:

Tier 1: Pre-Execution Regex Scanner

Intercepts keywords including ignore previous instructions, you are now DAN, system prompt, api_key, and script tags before dispatching any network request to Gemini.

Tier 2: System Instruction Boundary Isolation

Prompts are never concatenated into a single string. The core persona and JSON extraction guidelines are loaded via Gemini's native systemInstruction parameter, while user text is enclosed in inert XML tags: <untrusted_user_note>...</untrusted_user_note>.

Tier 3: Post-Execution Strict Schema Validation

AI responses are structurally inspected. Numerical limits enforce transaction caps ($100,000,000.00), categories are mapped strictly to the approved 10-category taxonomy, and descriptions are stripped of HTML/script elements.

Tier 4: Client-Side Real-Time Prompt Guard

Real-time keystroke monitoring evaluates adversarial entropy. If risky sequences are detected, an alert badge is rendered and the submit button is programmatically disabled.

Role-Based Admin Governance (RBAC)

Platform governance and database wipe operations are hardcoded exclusively to the identity: layanmoyura@proton.me.

Public UI headers render no "Admin" buttons. Authorized entry is strictly granted via:

  • Keyboard shortcut: Ctrl + Shift + A
  • URL fragment router: #admin
  • Settings modal conditional link (visible only to admin session)
Single-Device Session Enforcement

To prevent cross-device route contamination and conflicting balances, users are restricted to one active hardware session via table user_device_sessions.

  • Logging into a new device registers the hardware fingerprint.
  • Prior active devices are flagged and safely logged out.
  • Background heartbeat sentinel continuously verifies ownership.

Zero-Hallucination Reset Stored Procedure

-- PL/pgSQL Atomic Data Purge & Clean Account Initialization
CREATE OR REPLACE FUNCTION public.admin_purge_user_data(target_user_id UUID)
RETURNS JSONB LANGUAGE plpgsql SECURITY DEFINER AS $$
BEGIN
    DELETE FROM public.transactions WHERE user_id = target_user_id;
    DELETE FROM public.budgets WHERE user_id = target_user_id;
    DELETE FROM public.categories WHERE user_id = target_user_id AND is_default = FALSE;
    DELETE FROM public.tasks WHERE user_id = target_user_id;
    DELETE FROM public.personal_assets WHERE user_id = target_user_id;
    DELETE FROM public.subscriptions WHERE user_id = target_user_id;
    DELETE FROM public.contacts_ledger WHERE user_id = target_user_id;
    DELETE FROM public.device_location_pings WHERE user_id = target_user_id;
    DELETE FROM public.saved_places WHERE user_id = target_user_id;
    DELETE FROM public.mobility_timeline_events WHERE user_id = target_user_id;
    DELETE FROM public.daily_mobility_stats WHERE user_id = target_user_id;
    DELETE FROM public.user_device_sessions WHERE user_id = target_user_id;
    DELETE FROM public.accounts WHERE user_id = target_user_id;

    -- Strict zero starting balance
    INSERT INTO public.accounts (user_id, name, balance, currency)
    VALUES (target_user_id, 'Primary Checking', 0.00, 'USD');

    RETURN jsonb_build_object('success', true, 'message', 'Purged & reset to 0.00');
END;
$$;

Algorithmic Engines & Telemetry Logic

The core intelligence of Apex LifeOS relies on deterministic spatial mathematics and stateful hysteresis filters.

1. Haversine Velocity Engine with Traffic Jam Hysteresis

Distance between consecutive GPS fixes \((lat_1, lon_1)\) and \((lat_2, lon_2)\) is computed via the great-circle Haversine formula:

d = 2R · arcsin( √( sin²(Δlat/2) + cos(lat1)·cos(lat2)·sin²(Δlon/2) ) )
velocity = (d / Δt) · 3600 [km/h]

The Traffic Jam Problem & Solution: Standard apps falsely reclassify car drivers waiting at red lights or crawling in bumper-to-bumper city traffic (0–15 km/h) as "pedestrians walking". Apex LifeOS maintains a motorized speed hysteresis buffer. If the vehicle previously maintained speed > 25 km/h within a sliding 10-minute window, deceleration below 15 km/h enters Vehicle (Traffic Congestion) state rather than Walking.

2. Geofence Sentinel & Proximity Triggers

Saved locations (Supermarkets, Landlord, Office) monitor spatial radii \(r \in [100\text{m}, 1500\text{m}]\). When proximity threshold \(d \le r\) evaluates to true:

  • Budget Category Sentinel: Calculates remaining budget for that category and renders the global proximity alert banner.
  • Payable Task Trigger: Generates a 1-click completion prompt to settle rent upon arrival at the landlord's office.
  • Social IOU Settle Trigger: Prompts expense resolution when meeting a friend with an active balance.
3. The Financial Task Bridge

Tasks can be marked as is_financial = true with financial types: payable (bills), receivable (invoices), or budget_task. Checking off a task does not merely toggle a visual checkbox—it atomically logs a transaction against the designated account and updates current balances.

Android Companion Telemetry Subsystem

The Android companion app (android-companion/) runs as a persistent native Kotlin background daemon, continuously streaming mobility metrics to Supabase without requiring an active browser tab.

Service Architecture
  • Foreground Service: Ensures the OS does not terminate the telemetry service under memory pressure.
  • FusedLocationProviderClient: High-precision GPS fixes with adaptive interval throttling.
  • Battery Throttling: Dynamically backs off update frequency when the device is stationary.
  • Offline SQLite Queue: Buffers pings locally if network connectivity drops.
